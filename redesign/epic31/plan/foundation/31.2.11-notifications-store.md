# [31.2.11] ui — notifications persisted per user + school, list renders incrementally

## Goal
The bell's history survives a reload and a school switch-and-back (stored in the browser per user + school, newest 1000 kept), one school's notifications are still never visible under another, logout still wipes them, and `NotificationList` renders 20 rows at a time and adds more as the user scrolls — no API, no new dependency (D4).

## Steps
1. **Read first:** the header comment and every test of `ui/src/api/notification-state.ts` / `.test.ts` — the isolation contract below must keep all of them passing except the cap number; `ui/src/api/form-draft-storage.ts:1-75` (the repo's pattern for a tenant-scoped `localStorage` key with silent failure and a logout purge); `ui/src/api/auth-state.ts:46-50,117-130` (`currentSessionGeneration()` is bumped only by `clearAuthState()` — logout, session expiry, failed refresh); `ui/src/api/session.ts:69-72` (`decodeAccessTokenSubject` = the user id from the JWT `sub`).

2. **Isolation contract (must hold exactly as today).**
   | Today (`notification-state.ts`) | After |
   |---|---|
   | `pushNotification` drops a record whose captured `tenantId` ≠ active tenant (`:72`) | unchanged |
   | tenant switch → in-memory list cleared (`:103-113`) | tenant switch → in-memory list **replaced** by the new school's stored list (empty if none). A's records are never in memory while B is active. |
   | logout (`clearAuthState`) → list cleared | logout → list cleared **and every stored `notifications:v1:*` key removed** (same rule as form drafts, `form-draft-storage.ts:12-15`: the next person at this browser must not see them) |
   | — | records read back from storage are filtered to `record.tenantId === activeTenant` (defence in depth against a tampered or mis-keyed entry) |

3. **Key and storage helpers** (module-private, in `notification-state.ts`):
   ```ts
   const STORAGE_PREFIX = 'notifications:v1:';
   const MAX_NOTIFICATIONS = 1000; // D4
   function storageKey(): string | null {
     const token = getAccessToken();
     const tenantId = getActiveTenant();
     const userId = token ? decodeAccessTokenSubject(token) : null;
     return userId && tenantId ? `${STORAGE_PREFIX}${userId}:${tenantId}` : null;
   }
   ```
   - `readStored(key)`: `JSON.parse(localStorage.getItem(key))`, keep only array items that have string `id`, `message`, `createdAt`, boolean `read`, a known `variant`, and `tenantId === getActiveTenant()`; `slice(0, MAX_NOTIFICATIONS)`; any throw → `[]`.
   - `writeStored()`: `const key = storageKey(); if (key) localStorage.setItem(key, JSON.stringify(notifications));` inside `try {} catch {}` (quota or blocked storage just doesn't persist — same as `form-draft-storage.ts`). With no key (signed out, or no school chosen yet) the list lives in memory only, which is what every existing test with `tenantId: null` exercises.
   - `purgeStored()`: collect every `localStorage` key starting with `STORAGE_PREFIX`, then remove them (collect first, remove after — clone `clearAllFormDrafts`, `form-draft-storage.ts:53-70`).
   - Import `getAccessToken`, `currentSessionGeneration` from `./auth-state` and `decodeAccessTokenSubject` from `./session`. No import cycle: `session.ts → client.ts → auth-state.ts`, none of which imports this module.

4. **Mutations.** `pushNotification` (cap `MAX_NOTIFICATIONS`), `markNotificationRead`, `markAllNotificationsRead` and `clearNotifications` each call `writeStored()` after changing `notifications` and before `notifyNotificationStateChange()`. Update the cap comment (`:35-38`): 1000 per D4.
   Add a `ponytail:` line above `writeStored`: `// ponytail: last writer wins across tabs; listen for the "storage" event if two open tabs must merge their histories.`

5. **Auth subscription** (replaces `:103-113`):
   ```ts
   let lastKey = storageKey();
   let lastGeneration = currentSessionGeneration();
   notifications = lastKey ? readStored(lastKey) : [];
   subscribeAuthState(() => {
     if (currentSessionGeneration() !== lastGeneration) {   // logout / expiry / failed refresh
       lastGeneration = currentSessionGeneration();
       purgeStored();
     }
     const key = storageKey();
     if (key === lastKey) return;                            // e.g. a token refresh for the same user
     lastKey = key;
     notifications = key ? readStored(key) : [];
     notifyNotificationStateChange();
   });
   ```
   On logout `clearAuthState()` nulls token and tenant, so the key becomes `null` and the list empties in the same callback. Update the module header comment: history is now stored per user + school (D4) and purged at logout.

6. **`notification-list.tsx` — incremental rendering.** New optional prop `pageSize?: number` (default 20; JSDoc: "rows rendered per step; more are added when the end of the list scrolls into view").
   - `const [visibleCount, setVisibleCount] = React.useState(pageSize);` render `notifications.slice(0, visibleCount)`.
   - When `visibleCount < notifications.length`, render a last `<li data-list-sentinel ref={sentinelRef} className="p-2 text-caption text-text-secondary">{t('notifications.loadingMore', { ns: 'common' })}</li>`; when everything is shown and `notifications.length > pageSize`, render `<li className="p-2 text-caption text-text-secondary">{t('notifications.endOfList', { ns: 'common' })}</li>` instead. Both keys are added to `common.json` by 31.1.2a ("Loading more…" / "আরও লোড হচ্ছে…", "That's everything." / "আর কোনো বিজ্ঞপ্তি নেই।"); the file's own `useTranslation('nav')` stays the first call, so pass `ns: 'common'` explicitly (`ui/scripts/check-i18n-keys.mjs` resolves bare keys to the first namespace).
   - Effect on `[visibleCount, notifications.length, pageSize]`: if no sentinel, return; if `typeof IntersectionObserver !== 'function'` → `setVisibleCount(notifications.length)` (render everything — jsdom and very old browsers; same `typeof X === 'function'` guard as `app-shell.tsx:430`); else `new IntersectionObserver(([entry]) => { if (entry?.isIntersecting) setVisibleCount((c) => c + pageSize); })`, observe the sentinel, disconnect on cleanup. Default `root` (viewport): the observer clips by scrolling ancestors, so it works both inside the bell's `max-h-80` popover list and on the full `/notifications` page.
   - **Unread dot** (shared request admin/notifications): the message row `flex items-center gap-2` (`notification-list.tsx:81`) → `flex items-start gap-2`, and the dot (`:83`) gets `mt-2` so it sits beside the first line of a wrapped message.
   - Nothing else changes (rows, empty state, variants). `notification-bell.tsx` and `client-admin/src/routes/_staff/notifications.tsx` pass no new prop and get incremental rendering for free.

7. **Story.** `notification-list.stories.tsx`: add `Long` — 300 generated records, inside a `max-h-80` wrapper, so scrolling shows rows being appended.
