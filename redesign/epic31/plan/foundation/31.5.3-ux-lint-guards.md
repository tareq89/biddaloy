# [31.5.3] guards — ESLint rules for native pickers, raw dates, page widths and row actions

## Goal
The four mechanically checkable rules of D37 fail lint — in CI, in the pre-commit hook and in the pre-push hook — with a reviewable allow-list for the legitimate exceptions, so wave 4's work cannot quietly regress.

## Files
- `ui/eslint-rules/ux-guards.mjs` (new) — one plugin, four rules
- `ui/eslint-rules/ux-guards.spec.mjs` (new) — `RuleTester` cases
- `ui/eslint-config.mjs` (changed) — export `uxControlsGuardConfig` and `uxPageGuardConfig`; document them in the header list
- `ui/eslint.config.mjs` (changed) — apply the controls guard to `src/**`, with its allow-list
- `client-admin/eslint.config.mjs` (changed) — apply both guards, with their allow-lists
- whatever straggler files the first lint run reports (step 7) — expected few after wave 4

No CI or hook file changes (step 6 explains why).

## Steps
1. **Why ESLint, not a script.** All four checks are syntax checks, and ESLint already runs everywhere it needs to run (step 6). A hand-rolled script like `ui/scripts/check-i18n-keys.mjs` would need its own CI step and hook wiring for no gain, so no script is added. Why a small plugin instead of `no-restricted-syntax`: in flat config, a rule set in two overlapping `files` blocks takes the options of the last block only, and the guards need different file scopes (all `src` vs. route/page files). A separate rule id per guard also gives each guard its own allow-list and its own `eslint-disable-next-line` name. Each rule is still a handful of AST visitors.
2. **Clone sources:** module shape and `export default { rules: { … } }` from `ui/eslint-rules/no-window-alert.mjs`; the className-text scan (JSXAttribute `className`/`class`, `sourceCode.getText(node.value)`, token regex, per-token `loc` from `getLocFromIndex`) from `ui/eslint-rules/logical-properties.mjs:16-91`; the JSX-enabled `RuleTester` from `ui/eslint-rules/component-boundary.spec.mjs:28-40`. Specs under `ui/eslint-rules/**/*.spec.mjs` already run in vitest (`ui/vitest.config.ts:5`).
3. **`ui/eslint-rules/ux-guards.mjs`** — plugin with four rules (messages name the replacement and the decision):
   - `no-native-picker` (D25): report `JSXOpeningElement` named `select`; report a `JSXOpeningElement` named `input` whose `type` attribute is the literal `date | time | month | week | datetime-local` (string literal or `{'…'}` expression literal). Message: use `Select`/`Combobox`, or `DatePicker`/`MonthPicker`/`TimeInput` from `@biddaloy/ui/components`.
   - `no-raw-date-display` (D5, D7): report a `CallExpression` whose callee property is `toLocaleDateString` or `toLocaleTimeString`; report `toLocaleString` when the receiver is `new Date(…)`; report `slice | substring | substr | split` called on the result of `.toISOString()`. Message: `formatDate` / `formatDateTime` / `formatTime` for screen text, the ISO helper from `@biddaloy/ui/utils` (`toIsoDate`, added by 31.1.2b) for API calls and URLs. Add `// ponytail: a Date held in a variable and shown via .toLocaleString() is not caught — needs type info; extend boundary/no-raw-intl's number check to Date if it shows up.`
   - `no-page-max-width` (D15, D21): in `className`/`class` text, report a token whose last `:`-segment matches `/^max-w-(md|lg|xl|[2-7]xl|screen-[a-z0-9]+|prose)$/` (so `md:max-w-3xl` is caught). `max-w-xs`, `max-w-sm`, `max-w-full`, `max-w-none` and arbitrary `max-w-[…]` stay allowed (truncated cells, inline widths). Message: page width comes from `PageContainer`; dialog width from the `Dialog` `size` prop.
   - `row-actions-column` (D19): on a `Property` with key `id` and string value `'actions'` whose parent is an `ObjectExpression`, report when `sourceCode.getText(parentObject)` does not contain `RowActions`. Message: table action columns render `<RowActions>` from `@biddaloy/ui/components`.
4. **`ui/eslint-config.mjs`**: import the plugin once and export two frozen configs in the existing style (see `noWindowAlertConfig`):
   - `uxControlsGuardConfig` = `{ plugins: { 'ux-guards': plugin }, rules: { 'ux-guards/no-native-picker': 'error', 'ux-guards/no-raw-date-display': 'error' } }`
   - `uxPageGuardConfig` = same plugin object, rules `ux-guards/no-page-max-width` and `ux-guards/row-actions-column`.
   Add both to the header's "Supported exports" list with one line each, citing D37.
5. **Wire and allow-list.** The allow-list is the `ignores` array of each block, one comment per entry saying why; a single line inside an otherwise-clean file uses `// eslint-disable-next-line ux-guards/<rule> -- <reason>` instead.
   - `ui/eslint.config.mjs`: `{ files: ['src/**/*.{ts,tsx}'], ignores: ['src/utils/**' /* the formatters themselves */, 'src/test/**' /* fixture builders */, 'src/**/*.test.{ts,tsx}', 'src/**/*.stories.tsx'], ...uxControlsGuardConfig }`. `ui` does not get the page guard (it has no route files; `DataTable` itself defines the actions column contract).
   - `client-admin/eslint.config.mjs`: `{ files: ['src/**/*.{ts,tsx}'], ignores: ['src/**/*.test.{ts,tsx}'], ...uxControlsGuardConfig }` and `{ files: ['src/routes/**/*.tsx', 'src/pages/**/*.tsx', 'src/features/**/*.tsx', 'src/components/**/*.tsx'], ignores: ['src/**/*.test.tsx', 'src/components/print/editor/**' /* desktop canvas editor, not redesigned (D2) */], ...uxPageGuardConfig }`. Both blocks after the existing guard blocks. None of the four rules needs type info, so they also run under `ESLINT_FAST=1`.
6. **Already wired — verify, don't add.** `.github/workflows/ci.yml:150` runs `yarn workspace @biddaloy/ui lint` and `:160` runs `yarn workspace @biddaloy/client-admin lint` (both `eslint .`); the pre-commit hook (`.husky/pre-commit` → `lint-staged.config.mjs` → `scripts/lint-staged-eslint.mjs`) runs ESLint on staged `ui/**` and `client-admin/**` files; the pre-push hook (`.husky/pre-push` → `yarn run check --affected` → `scripts/check.mjs` `buildLintCommand`) runs ESLint on changed files. Confirm by staging a file with `<select>` and watching `git commit` fail, then unstage.
7. **First run.** `yarn workspace @biddaloy/client-admin lint && yarn workspace @biddaloy/ui lint`. Expected after wave 4: few hits. On `main@93fa3e3f` the counts were: native `<select>` in 10+ files (mostly `client-admin/src/pages/settings/*`, `routines/index.tsx`, `routines/substitutions.tsx`), native date/time inputs in 22 files, 17 `toISOString()` slices (incl. `ui/src/hooks/programs.ts:364`, `ui/src/components/calendar/{agenda-list,month-grid}.tsx`), 7 `toLocale*String` (5 under `client-admin/src/routes/_platform/`), 68 container `max-w-*` tokens in routes/pages, 23 `id: 'actions'` columns. For each remaining hit: fix it when the fix is mechanical (ISO slice → `toIsoDate`, `toLocale*` → `formatDate`/`formatDateTime`/`formatTime`); otherwise add an allow-list entry with a reason that names the follow-up, and list those entries in the PR description so they can become issues. Do not redesign a page in this ticket.

## Tests
- `ui/eslint-rules/ux-guards.spec.mjs`, per rule: valid + invalid cases. `no-native-picker`: `<select>` invalid, `<input type="date">` / `type={'month'}` invalid, `<input type="text">` and `<Select>` valid. `no-raw-date-display`: `d.toLocaleDateString()`, `new Date(x).toLocaleString()`, `new Date().toISOString().slice(0, 10)`, `.toISOString().split('T')[0]` invalid; `n.toLocaleString()` on a non-`new Date` receiver, `formatDate(d)`, `d.toISOString()` alone valid. `no-page-max-width`: `className="mx-auto max-w-3xl"`, `className={cn('md:max-w-screen-xl', x)}` invalid; `max-w-xs truncate`, `max-w-[12rem]`, `max-w-full` valid. `row-actions-column`: `{ id: 'actions', cell: () => <button /> }` invalid; `{ id: 'actions', cell: () => <RowActions actions={a} /> }` and `{ id: 'name' }` valid.
- Full `yarn workspace @biddaloy/ui lint` and `@biddaloy/client-admin lint` green.
