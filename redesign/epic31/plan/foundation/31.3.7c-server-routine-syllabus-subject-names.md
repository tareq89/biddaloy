# [31.3.7c] server — routine slots and syllabus topics carry subject names (families can name subjects)

## Goal
Guardians and students (who get 403 on `GET /subjects`) see subject names on `/portal/routine` and `/portal/syllabus`: each resolved routine slot and each syllabus topic carries `subject_name_en` / `subject_name_bn`, read with a tenant-scoped lookup. For syllabus this fills two fields the client type already declares but the server never sets (a confirmed gap, `ui/src/hooks/syllabus.ts:15-16`).

## Files
- `server/src/modules/routines/dto/resolve.dto.ts` (changed) — `ResolvedSlot` gains the two fields.
- `server/src/modules/routines/resolve-routine.service.ts` (changed) — one subject lookup per call.
- `server/src/modules/routines/resolve-routine.service.spec.ts` (changed).
- `server/src/modules/routines/routine-slots.service.integration.spec.ts` (changed — or a new `resolve-routine.service.integration.spec.ts` cloned from its setup if resolve has no real-DB spec yet).
- `ui/src/hooks/routines.ts` (changed) — `ResolvedSlot` mirror (`:627-641`) only.
- `server/src/modules/homework/syllabus.service.ts` (changed) — `findAll` loads the subject.
- `server/src/modules/homework/dto/syllabus.dto.ts` (changed) — response DTO + mapper carry the names.
- `server/src/modules/homework/syllabus.service.spec.ts` (changed).
- `server/src/modules/homework/syllabus.controller.e2e-spec.ts` (changed) — family read returns names.

## Steps
1. **Read first:** `server/CLAUDE.md`, `.claude/skills/multi-tenancy/SKILL.md`. No route/guard/permission change. `Subject` columns: `name_en` (not null), `name_bn` (nullable), soft-deletable (`academics/entities/subject.entity.ts:42-61`). Both modules already register `Subject` in `TypeOrmModule.forFeature` (`routines.module.ts:71`, `homework.module.ts:64`).
2. **Routine resolve** (request from portal-5). `resolve-routine.service.ts`: inject `@InjectRepository(Subject) private readonly subjectRepo: Repository<Subject>`. After the slots query (`:126`) and next to the period-slot/teacher queries (`:139-141`), add to the same `Promise.all`:
   ```ts
   this.subjectRepo.find({
     where: { id: In(subjectIds), tenant_id: tenantId },
     withDeleted: true,                       // a slot of a since-deleted subject still names it
     select: { id: true, name_en: true, name_bn: true },
   }),
   ```
   with `subjectIds = [...new Set(slots.map((s) => s.subject_id))]`; when building each result (`:190`) set `subject_name_en: subject?.name_en ?? null, subject_name_bn: subject?.name_bn ?? null`. `resolve.dto.ts` `ResolvedSlot`: add both as `string | null` with a one-line comment (families cannot call `/subjects`). Update the mirror in `ui/src/hooks/routines.ts`. `workload.service.ts` also uses this service — it ignores extra fields; check its spec still passes.
3. **Syllabus list** (request from portal-8). `syllabus.service.ts:87-92`:
   ```ts
   return this.repo.find({
     where: { ...where, subject: { tenant_id: tenantId } },
     relations: { subject: true },
     withDeleted: true,   // only affects the joined subject: `SyllabusTopic` has no deleted_at of its own (entity checked)
     order: { sequence: 'ASC' },
   });
   ```
   `dto/syllabus.dto.ts`: add `@ApiProperty({ type: String, nullable: true }) subject_name_en: string | null;` and `subject_name_bn` to `SyllabusTopicResponseDto`, and in `toSyllabusTopicResponseDto` (`:115-125`) `subject_name_en: topic.subject?.name_en ?? null, subject_name_bn: topic.subject?.name_bn ?? null`. Other callers of the mapper (create/update responses) pass topics without the relation → `null`, which the client already tolerates (`portal:syllabus.unknownSubject`).
4. Do not regenerate `schema.d.ts` (31.3.7d does it once for the lane; it will pick up the syllabus DTO change).

## Tests
- `resolve-routine.service.spec.ts`: mock `subjectRepo.find` → slots carry `subject_name_en`/`subject_name_bn`; assert it was called with `where.tenant_id = TENANT_A` and `withDeleted: true`; a slot whose subject is not returned gets `null`s.
- Real-DB spec: a PARENT-scoped resolve (`student_id`) returns the subject names; a slot pointing at a tenant-B subject id returns `null` names (cross-tenant isolation); a soft-deleted subject still names its slot.
- `syllabus.service.spec.ts`: `findAll` passes `relations.subject` and `where.subject.tenant_id`; the mapper emits the names.
- `syllabus.controller.e2e-spec.ts`: as PARENT, `GET /syllabus-topics?class_id=` rows carry `subject_name_en`.
