# [31.2.1b] ui — numerals in `{{count}}`, `formatPhone` as `01711-000004`, number/currency never throw on missing values

## Goal
Every number interpolated into a translation (`{{count}}`, `{{total}}` …) follows the numeral
system (B24, D6); phones display as `01711-000004` everywhere and never throw (D8, B22, C20);
`formatNumber` / `formatCurrency` / `formatServerAmount` show `—` for a missing value instead of
crashing the page.

## Steps
1. **i18next numeral formatter (B24).** Interpolation has no digit handling today
   (`i18n.ts:51-64`). i18next 26 always installs its built-in `Formatter`, which returns the value
   untouched when no format name is given (`node_modules/i18next/dist/esm/i18next.js:1433-1434`),
   so `interpolation.alwaysFormat` alone does nothing; a formatter **module** replaces it. In `i18n.ts`:
   ```ts
   import type { FormatterModule } from 'i18next';
   import { renderDigits } from '../utils/digits';
   import { LOCALE_REGION_DEFAULTS, type NumeralSystem } from './region-config';

   /** Tenant override pushed by RegionConfigProvider; undefined → follow the language. */
   let tenantNumerals: NumeralSystem | undefined;
   export function setInterpolationNumerals(numerals: NumeralSystem | undefined): void {
     tenantNumerals = numerals;
   }

   /** D6/B24: a number interpolated into any string ({{count}}, {{total}}, …) is rendered in the
    * active numeral system. Strings are never touched — registration numbers, phones and codes
    * stay Latin (D6) as long as callers pass them as strings. No grouping on purpose: a `{{year}}`
    * must not become ২,০২৬ — use formatNumber for grouped amounts. */
   const numeralFormatter: FormatterModule = {
     type: 'formatter',
     init() {},
     add() {},
     addCached() {},
     format: (value, _format, lng) => {
       if (typeof value !== 'number') return value;
       const numerals =
         tenantNumerals ?? LOCALE_REGION_DEFAULTS[lng as keyof typeof LOCALE_REGION_DEFAULTS]?.numerals ?? 'latin';
       return renderDigits(String(value), numerals);
     },
   };
   ```
   Chain `.use(numeralFormatter)` after `.use(backend)` and set
   `interpolation: { escapeValue: false, alwaysFormat: true }`. Named formats (`{{x, number}}`)
   stop working with the built-in formatter gone — none exist (`rg "\{\{\w+, " ui/src/i18n/locales`
   → 0 hits); say so in a comment. Plural selection is unaffected (it reads `count` before
   interpolation). Check `digits.ts → region-config.ts` creates no import cycle with `i18n.ts` (it
   does not today).
2. **Provider pushes the tenant numerals.** `region-config-provider.tsx`: inside
   `RegionConfigProvider`, after `resolved` (`:26`), call `setInterpolationNumerals(resolved.numerals)`
   **during render** (children call `t()` in the same render pass, before any effect runs) and add
   `React.useEffect(() => () => setInterpolationNumerals(undefined), [])` so a test or an unmounted
   route does not leak its numerals. Comment with `ponytail:` — a module-level value, last mounted
   provider wins; a component that does not re-render after tenant settings load keeps the
   language-default digits until its next render; upgrade path is a numerals field in i18next's
   per-instance options if two tenants ever render at once.
3. **Phone display (D8, B22, C20).** `utils/phone.ts` `formatPhone` (`:39-54`) becomes:
   ```ts
   /** D8 display form (`01711-000004`, Latin digits always — D6). Never throws (C20): empty → '—',
    * a number the region cannot parse is shown as typed. */
   export function formatPhone(value: string | null | undefined, config: RegionConfig): string {
     const raw = (value ?? '').trim();
     if (raw === '') return '—';
     const result = parsePhone(raw, config);
     if (!result.valid) return raw;
     const digits = result.value;
     let nextDigit = 0;
     return config.phone.displayFormat.replace(/X/g, () => digits[nextDigit++] ?? '') + digits.slice(nextDigit);
   }
   ```
   (No `+country` prefix any more. There is no `tel:` link or SMS caller of `formatPhone` today —
   `rg "tel:" ui/src client-admin/src` is empty — so no E.164 helper is added.) In
   `region-config.ts` `REGION_BD_BN.phone` (`:84-89`): `example: '01712-345678'`,
   `displayFormat: '0XXXX-XXXXXX'` — the trunk `0` is data in the mask, not code; update the
   `displayFormat` doc comment (`:44-48`) example accordingly. Also refresh the `date.format`
   comment (`:27-31`): `formatDate` is long-form now (D5), the field is unused.
4. **Tenant phone block the client cannot read.** Stored tenant settings come from the server
   default `country: 'BD'`, pattern `'^(?:\+?880|0)1[3-9]\d{8}$'`, mask `'+880 XXXX-XXXXXX'`
   (`server/src/modules/schools/settings/tenant-settings-defaults.ts:37-42`). `parsePhone`
   expects a calling code and a national-number pattern, so on the ~38 routes wrapped in
   `RegionConfigProvider value={useTenantRegionConfig()}` every phone fails to parse — that is
   B22's "three formats". In `region-config-resolver.ts` (`:53-58`) take the tenant `phone` block only
   when `/^\d+$/.test(tenantRegion.phone?.country ?? '')`; otherwise use `fallback.phone`. Comment
   with `ponytail:` and the upgrade path (server stores the client shape → delete the guard).
5. **Missing values never crash display.**
   - `number.ts` `formatNumber(value: number | null | undefined, …)`: `if (value == null || !Number.isFinite(value)) return '—';`
   - `currency.ts` `formatCurrency(amountMinorUnits: number | null | undefined, …)`: return `'—'`
     for `null`/`undefined`/`NaN` **before** the existing `Number.isSafeInteger` guard (`:23`). A
     finite non-integer still throws — that guard catches a caller passing taka instead of paisa
     and stays. `formatServerAmount(amount: number | string | null | undefined, …)` (`:137`):
     `null`/`undefined`/`''` → `'—'`.
6. **e2e translator.** `e2e/i18n.ts` `makeT` (`:239-255`): when `locale === 'bn'` and a param is a
   `number`, interpolate it with Bengali digits (`String(v).replace(/\d/g, (d) => '০১২৩৪৫৬৭৮৯'[Number(d)])`);
   strings unchanged. Without this, every bn spec that passes `{ count: 2 }` expects `2` while the
   page shows `২`.
