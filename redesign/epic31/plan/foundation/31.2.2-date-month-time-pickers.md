# [31.2.2] ui — DatePicker (button trigger, month header, today ring), MonthPicker, TimeInput

## Goal
The three pickers look and behave like `PATTERN: DatePicker`, `PATTERN: MonthPicker` and
`PATTERN: TimeInput` (`PLAN/kit/patterns.html` — `grep -n "PATTERN: DatePicker"`): a full-width
trigger button showing the formatted value or a placeholder, a popover with the shared
`MonthHeader`, today ringed, the selected value filled. No typed `YYYY-MM-DD` box, no native
control. Existing `DatePicker` callers keep compiling unchanged.

## Steps
1. **Shared trigger look.** All three triggers use the Control classes from `PLAN/kit/patterns.md` §1
   with one change: height comes from the density variable like `primitives/input.tsx:16`, so portal
   and phone stay 44 px and staff desktop 32 px:
   `flex h-[var(--control-h,2rem)] w-full items-center justify-between gap-2 rounded-md border border-border-functional bg-surface px-3 text-start text-body-lg text-text-primary md:text-body`
   + `text-text-secondary` when empty + the focus ring from `primitives/button.tsx` (`focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background outline-none`)
   + `disabled:cursor-not-allowed disabled:bg-muted`. Icon on the end side, `size-4 text-text-secondary`,
   `aria-hidden`. Logical classes only (lint rule in `ui/eslint.config.mjs:76-79`).
2. **`DatePicker` props.** Replace `DatePickerProps` (`date-picker.tsx:21-29`) with:
   ```ts
   export interface DatePickerProps
     extends Omit<React.ComponentProps<'button'>, 'value' | 'onChange' | 'children' | 'aria-label' | 'type'> {
     value: Date | undefined;
     onValueChange: (date: Date | undefined) => void;
     config: RegionConfig;
     'aria-label': string;
     placeholder?: string;   // default t('date.pick') — "তারিখ বাছুন" / "Pick a date"
     min?: Date;             // inclusive
     max?: Date;             // inclusive
   }
   ```
   `openCalendarLabel` / `previousMonthLabel` / `nextMonthLabel` are removed — no caller passes them
   (`rg "openCalendarLabel|previousMonthLabel|nextMonthLabel" client-admin/src` is empty); the
   month labels come from `MonthHeader`'s `t()` defaults. The rest props (`id`, `aria-describedby`,
   `aria-invalid`, `disabled` — what `FormControl` slots in) go on the trigger button.
3. **`DatePicker` body.** Drop the `Input`, the `text` state and the `parseDate` typing path
   (`:40-72`). Render `Popover` (`../primitives/popover`, as today) → `PopoverTrigger asChild` on
   `<button type="button" {...rest} aria-label={…}>` with text `value ? formatDate(value, config) : placeholder`
   and `CalendarIcon`. `PopoverContent className="w-fit rounded-lg border border-border-subtle bg-surface p-3 shadow-e2"`
   → `Calendar`. Selecting a day: `onValueChange(date)` and close (as `:87-90`). Keep `viewMonth`
   state, synced from `value` (`:44-47`).
4. **`Calendar` (same file, still not in `index.ts`).** Props become
   `{ month: Date; selected: Date | undefined; config: RegionConfig; min?: Date; max?: Date; onMonthChange; onSelect }`.
   - Header: `<MonthHeader label={formatMonth(month, config)} onPrevious onNext onToday />` (`./month-header`);
     `onToday` moves the view to today's month and the roving focus to today. Replaces `:197-221`.
   - Weekday row: keep the `Intl` weekday labels (`:148-151`) but start the week at
     `config.date.firstDayOfWeek` (rotate, like `month-grid.tsx:105-111`); classes
     `grid grid-cols-7 text-center text-caption text-text-secondary`, cells `h-8`.
   - Days: full weeks — leading days of the previous month and trailing days of the next month are
     real buttons with `text-text-secondary opacity-60`; clicking one selects it and moves the view.
     Replace the `null` blanks (`:135-138`, `:244-248`).
   - Day button (keep `role="gridcell"`, roving `tabIndex`, arrow/Enter/Space handling `:179-193`,
     `:275-292`, the `contents` rows `:222-227` and the focus-ring comment `:260-272`):
     `flex size-11 items-center justify-center rounded-md hover:bg-muted md:size-9` holding
     `<span className="flex size-7 items-center justify-center rounded-full text-label">` with the
     digits (`renderDigits`). States on the span: today `font-semibold text-primary ring-2 ring-primary ring-inset`;
     selected `bg-primary font-semibold text-primary-foreground` (wins over today). With **no value**,
     today gets the selected look and the initial roving focus (D26 "today is selected by default"),
     but `aria-selected` stays `false` until a real value exists.
   - Attributes for tests and e2e: `data-date={toIsoDate(date)}`, `data-today`, `data-outside`;
     `aria-label={formatDate(date, config)}` (a screen reader hears the full date, not "9").
   - `min`/`max`: days outside are `disabled` + `aria-disabled="true"`, skipped by click and Enter.
   - Grid `aria-label={t('date.calendar')}` instead of the literal `"Calendar"` (`:228`).
   - **Year jump** (shared request admission_slug: a date of birth ~10 years back must be reachable
     without 120 month clicks). `Calendar` keeps `const [view, setView] = React.useState<'days' | 'months'>('days')`.
     The header passes `onLabelClick={() => setView(v => v === 'days' ? 'months' : 'days')}` and
     `labelExpanded={view === 'months'}` to `MonthHeader` (props built by 31.1.2a). In `'months'` view the
     header label is the year (`renderDigits(String(year), config.numerals)`), prev/next step one year
     (`previousLabel={t('date.previousYear')}`, `nextLabel={t('date.nextYear')}`), no Today button, and the
     body is the same `grid grid-cols-3 gap-1` of 12 month buttons as `MonthPicker` (step 5 — extract one
     small module-private `MonthButtons({ year, selected, min, max, onPick, config })` in
     `month-picker.tsx`, export it from that file only (not `index.ts`), and use it in both). Picking a
     month sets the view month to it and returns to `'days'`; months entirely outside `min`/`max` are
     disabled. Esc in `'months'` view goes back to `'days'` before it closes the popover. ponytail: no
     decade view — a parent clicks "previous year" ~10 times; add one if a 50-year range ever matters.
5. **`MonthPicker`** (props are final from 31.1.2a; take `config` from `useRegionConfig()`):
   trigger per step 1 with `CalendarRangeIcon`, text `value ? formatMonth(value, config) : (placeholder ?? t('date.pickMonth'))`.
   Popover `w-full rounded-lg border border-border-subtle bg-surface p-3 shadow-e2 md:w-72`, header
   `<MonthHeader label={renderDigits(String(viewYear), config.numerals)} previousLabel={t('date.previousYear')} nextLabel={t('date.nextYear')} onPrevious onNext />`
   (no Today), then `grid grid-cols-3 gap-1` of 12 `<button type="button">`
   `h-11 rounded-md hover:bg-muted md:h-9`, label `formatMonthName(m, config)`, `aria-pressed` on the
   selected one, which gets `bg-primary font-semibold text-primary-foreground`; the current month gets
   the today ring. Months outside `min`/`max` (string compare on `YYYY-MM`) are disabled. Select →
   `onValueChange(\`${viewYear}-${String(m).padStart(2, '0')}\`)` and close. `viewYear` starts at the
   value's year, else this year.
6. **`TimeInput`** (props final from 31.1.2a): keep it a thin wrapper over `Combobox` (`./combobox`
   — focus stays in the input, typing filters; do not rebuild the listbox). Options: every
   `stepMinutes` (default 30) from `min` (default `'00:00'`) to `max` (default `'23:59'`), value
   `HH:mm`, label `formatTime(v, config)`; if `value` is off the step grid (data saved as `08:10`),
   insert it in order so it still shows. Wrap in `<div className="relative">`, give the Combobox
   `className="pe-9"` and put `ClockIcon` at `pointer-events-none absolute end-3 top-1/2 size-4 -translate-y-1/2 text-text-secondary`.
   Pass `placeholder ?? t('date.pickTime')`, `announceResults={(count) => t('combobox.results', { count })}`,
   `emptyText={t('table.empty')}`. The option row look in `PATTERN: TimeInput` (`h-11 md:h-8`, selected
   `bg-secondary` + check) belongs to `Combobox` itself — 31.2.7 restyles it; do not fork it here.
7. **DOM contract** (31.2.13b's `pickDate` and every later test rely on exactly this — do not rename):
   trigger = `<button>` named by its `aria-label` prop; popover = Radix `PopoverContent` (`role="dialog"`);
   month label = the `MonthHeader` label text (`formatMonth`); month buttons named `t('date.previousMonth')` /
   `t('date.nextMonth')`; each day = `role="gridcell"` button with `aria-label={formatDate(date, config)}`,
   `data-date="YYYY-MM-DD"` (Latin digits) and `data-outside` on days of the neighbouring months.
8. **e2e.** `e2e/journeys/calendar.spec.ts:48-49`: replace each `.fill(CREATE_DATE)` with: click
   the trigger (`page.getByLabel(t('calendar.eventForm.startDate'))`), and if
   `page.locator(\`[role="grid"] [data-date="${CREATE_DATE}"]\`)` is not visible click
   `page.getByRole('button', { name: t('common.date.nextMonth') })` (tomorrow can be next month), then
   click that `[data-date]` cell. Same for the end date.
