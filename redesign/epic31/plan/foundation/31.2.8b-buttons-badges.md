# [31.2.8b] ui — Button radius + disabled cursor, StatusBadge free tone, toast above the bottom bar, padded Card

## Goal
Buttons follow D29 (filled primary, outline, ghost, tinted `destructive` for inline use, filled `danger` only for `ConfirmDialog`) with `rounded-md`; `StatusBadge` accepts a tone + label for statuses that have no shared enum; toasts never cover the phone bottom bar; `Card` can carry the kit padding.

4. **`status-badge.tsx`**:
   - Extend the union (`:248-263`) with `| { tone: StatusTone; label: string; domain?: never; status?: never }` and give the existing members `tone?: never; label?: never`. Introduce `type StatusDomain = Exclude<StatusBadgeProps['domain'], undefined>` and use it in `statusLabelKey` (`:67`).

Icon `size-3.5 aria-hidden`.
5. **`toast.tsx`** — today `mobileOffset` only clears the home indicator and the comment (`:21-23`) calls overlapping the bottom bar a non-goal; D14 now makes the bar `fixed`, so toasts must sit above it below `md`. Sonner's own "mobile" switch is 600 px, the bar shows below 768 px, so read the breakpoint yourself:
   ```ts
   const BELOW_MD = '(max-width: 47.99rem)';
   function subscribe(cb: () => void) { if (typeof matchMedia !== 'function') return () => {}; const m = matchMedia(BELOW_MD); m.addEventListener('change', cb); return () => m.removeEventListener('change', cb); }
   const belowMd = React.useSyncExternalStore(subscribe, () => typeof matchMedia === 'function' && matchMedia(BELOW_MD).matches, () => false);
   const bottom = belowMd ? 'calc(5rem + var(--safe-area-bottom, 0px))' : undefined;
   ```
   Pass `offset={bottom ? { bottom } : undefined}` and `mobileOffset={{ bottom: bottom ?? 'calc(1rem + var(--safe-area-bottom, 0px))' }}` before `{...props}` (caller still wins). 5rem = the 4rem (`h-16`) bar + 1rem gap; it also clears `FullPageShell`'s footer. `ponytail:` guest pages below `md` (no bar) get the same lift — harmless; key it off a real "bar mounted" signal only if it ever looks wrong. Rewrite the `:14-23` comment.
6. **`card.tsx`** — add `padded?: boolean` (default `false`, so the 86 existing `<Card>` uses — many with their own `p-3.5`/`p-6`, or holding a table with no padding — render unchanged). `padded` adds `p-4 md:p-5` (D17) before `className` in the `cn`. Doc: "use `padded` for a content card; a card that holds a table or grid stays unpadded with `overflow-hidden`."
