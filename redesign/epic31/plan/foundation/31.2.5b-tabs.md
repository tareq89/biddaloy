# [31.2.5b] ui — DetailShell: tabs switch (B1), one left-aligned scrolling tab row, kit header

## Goal
On every detail page only the selected tab panel is shown (B1 fixed, visited panels keep their state), the tab row is one left-aligned underline row that scrolls sideways, and the header uses the PageHeader action rules plus an optional `facts` list (D20, D16). A detail page without tabs still uses `DetailShell` (`tabs` optional, body via `children` — CONTRACT Addendum 7), and the selected tab is scrolled into view on a phone.

## Steps
1. **Why B1 happens (verified in `node_modules/@radix-ui/react-tabs/dist/index.mjs:151-180`, v1.1.21)**: `TabsContent` renders `<Presence present={forceMount || isSelected}>` and gives the panel `hidden: !present`. `detail-shell.tsx:211` passes `forceMount` for every visited tab, so `present` is always `true` and a visited panel is never hidden — panels pile up. The props spread `...contentProps` comes **after** `hidden`, so a caller's own `hidden` wins.
2. **Fix (keeps the intent of `forceMount`)**: the file comment (`:9-17`) and the test at `detail-shell.test.tsx:163-193` show `forceMount` exists to keep a visited panel mounted so its local state (a typed note, a scrolled list) survives. Keep that and hide inactive panels with the native attribute:
   ```tsx
   <TabsContent key={tab.id} value={tab.id}
     {...(visited ? { forceMount: true } : {})}
     hidden={tab.id !== activeTab}>
   ```
   Use the `hidden` attribute, not a `data-[state=inactive]:hidden` class: it works without CSS (jsdom has no Tailwind, so only the attribute is testable), and Tailwind v4 preflight already maps `[hidden]` to `display: none`. Do **not** drop `forceMount` (C16 suggested it): dropping it unmounts the panel and loses unsaved input when the user switches tabs. Report this as the C16 resolution. Leave `TabsContent` in the primitive unchanged.
3. **`primitives/tabs.tsx` — the `line` look** (`variant="default"`, the pill, stays the default for segmented switches: `client-admin/src/routes/login.tsx:149`, `students/-detail/fees-tab.tsx:355`; conflicts.md D "Tabs primitive"). In `tabsListVariants` (`:22-35`) set
   `line: 'flex w-full justify-start gap-0 overflow-x-auto rounded-none border-b border-border-subtle bg-transparent p-0 [scrollbar-width:none] group-data-[orientation=horizontal]/tabs:h-auto'`
   (`cn` lets each of these replace its base counterpart: `flex`/`inline-flex`, `w-full`/`w-fit`, `justify-start`/`justify-center`, `p-0`/`p-[3px]`, and the same-variant height class).
   In `TabsTrigger` (`:52-91`) add line-only classes, all prefixed `group-data-[variant=line]/tabs-list:` — `h-11 md:h-10` (write the md one as `md:group-data-[variant=line]/tabs-list:h-10`), `flex-none shrink-0`, `rounded-none border-0 px-3`, `text-text-secondary hover:text-text-primary`, and for the selected tab `data-[state=active]:font-semibold data-[state=active]:text-primary`. Reuse the existing `after:` underline for the selected mark: for line it must be `after:bg-primary` and sit on the list's bottom border (`after:bottom-0`, 2 px = existing `after:h-0.5`) instead of `after:bottom-[-5px]` (that offset exists only for the pill's `p-[3px]`). Kit reference: tab `inline-flex h-11 shrink-0 items-center border-b-2 border-transparent px-3 whitespace-nowrap text-text-secondary hover:text-text-primary md:h-10`, selected `border-primary font-semibold text-primary` (`patterns.md` §4 "Tabs / DetailShell"). Check both variants in Storybook (`detail-shell.stories.tsx`, any Tabs story) light + dark.
4. **`detail-shell.tsx`**:
   - Types: `export type DetailShellAction = PageAction` and `export type DetailShellActionPriority = PageActionPriority` (import type from `./page-header`); the existing names stay exported, so `index.ts` and 12 callers are unaffected. Delete the local tiering (`:95-132`) and the inline action markup (`:144-186`).
   - Add `facts?: { label: string; value: React.ReactNode }[]` to `DetailShellProps`; keep `identifiers` (12 callers) with `@deprecated — use facts` in its doc.
   - **Optional tabs** (shared request payments_id; Addendum 7): `tabs?: DetailShellTab[]`, `activeTab?: string`, `onTabChange?: (tabId: string) => void`, new `children?: React.ReactNode`. When `tabs` is absent or empty, render no `Tabs` at all and put `children` under the header (inside the same `PageContainer`, so `space-y-6` spaces them). When `tabs` is non-empty, `activeTab` + `onTabChange` are required at runtime (dev `console.warn` if missing) and `children` is ignored. Existing 12 callers pass all three — no change for them.

   - Update the file comment `:9-17` to describe the `hidden` + `forceMount` pair and why.
5. **`e2e/pages/detail-shell.ts`** `openTab` — after the existing `tabpanel` visibility check add `await expect(this.page.getByRole('tabpanel')).toHaveCount(1);` (Playwright's role query skips hidden panels, so a B1 regression fails every detail journey). `clickAction` needs no change: on phone an outline action is `display:none` inline, so `inline.count()` is 0 and it falls through to "More actions".
