# [31.2.9b] ui — account menu holds language, theme, switch school; top-bar identity and icon buttons

## Goal
`UserMenu` can show the full account menu of D12 (name + role · school, Language, Theme, consumer rows such as Security, Switch school or role, Sign out) behind one opt-in prop; `TenantBar` shows school name + role chip + an icon switch button; the top-bar icon buttons are 44 px on phones; `LocaleSwitcher` gains the labelled outline trigger the guest pages need (31.2.12). Every existing caller renders as before until it opts in.

## Steps
1. **Read first:** `PLAN/kit/patterns.md` §10 "NavDrawer and AccountMenu"; `PLAN/kit/patterns.html` (`grep -n "PATTERN: AccountMenu"`); `PLAN/kit/starter.html:17-30` (desktop top bar: name `text-h3`, role chip, icon switch button, language/theme `hidden md:inline-flex`, account always).

2. **`locale-switcher.tsx` — extract, then add a trigger variant.**
   - Move the state and `handleValueChange` (`:47-57`) into `export function useLocaleSwitch(): { locale: Locale; choose: (value: string) => void; announcement: string; label: (l: Locale) => string }` (uses `LOCALE_LABELS` `:31-34`). `LocaleSwitcher` calls it; behaviour and the sr-only live region (`:81-83`) unchanged.
   - New prop `trigger?: 'icon' | 'labelled'` (default `'icon'`). `'labelled'` renders `Button variant="outline"` with `className="h-11 gap-2 px-4"`, `<LanguagesIcon />`, the current language name, `<ChevronDownIcon className="size-4 text-text-secondary" />`, and `aria-label={`${t('language.label')}: ${LOCALE_LABELS[locale]}`}` (label-in-name keeps the visible text inside the accessible name, WCAG 2.5.3). This is the switcher `PLAN/kit/starter-guest.html` shows; 31.2.12 uses it.
   - Icon trigger gets `className="size-11 md:size-9"` (patterns.md §3: top-bar icon buttons `size-11 md:size-9`).

3. **`theme-toggle.tsx` — extract.** Move `:36-47` (state + `handleValueChange`) into `export function useThemeSwitch(): { preference: ThemePreference; isDark: boolean; choose: (value: string) => void; announcement: string }`. `ThemeToggle` calls it; icon trigger gets `className="size-11 md:size-9"`.

4. **`tenant-bar.tsx` — extract the switch flow, restyle the bar.**
   - Move everything from `useQueryClient()` (`:76`) to `canSwitch` (`:143`) plus the confirm `Dialog` and the announcer (`:186-218`) into `export function useTenantSwitch()` returning `{ active, activeName, roleLabel, schoolLabel, otherSchools, rolesHere, canSwitch, request: (m: SchoolOption) => void, overlay: ReactNode }` where `overlay` is the confirm `Dialog` + sr-only live region (rendered once by whoever calls the hook). `active === undefined` means "render nothing", as today (`:97`).
   - `TenantBar` = `useTenantSwitch()` + markup:
     ```tsx
     <div className="flex min-w-0 items-center gap-2">
       <span className="min-w-0 truncate text-h3">{activeName}</span>
       <span className="hidden shrink-0 rounded-full bg-muted px-2 py-0.5 text-caption text-text-secondary md:inline">{roleLabel(active.role)}</span>
       {canSwitch && <Menu>…trigger: Button variant="ghost" className="size-11 shrink-0 text-text-secondary md:size-9" aria-label={rolesHere.length > 0 ? t('tenantBar.switchSchoolOrRole') : t('tenantBar.switchSchool')} → <ArrowLeftRightIcon /> … same MenuContent as :158-183</Menu>}
       {overlay}
     </div>
     ```
     The button's accessible name stays the translated "Switch school or role" / "Switch school", so `e2e/pages/app-shell.ts` `openSchoolSwitcher()` and `client-admin/src/routes/__root.test.tsx:240` keep working. Note the role chip is now hidden below `md` — `tenant-bar.test.tsx:45` "role as always-visible text" must assert presence in the DOM, not visibility (jsdom has no layout, so it already does; keep it, rename to "renders the role chip").

5. **`user-menu.tsx` — opt-in account controls (D12).** New prop:
   ```ts
   /** D12: adds Language, Theme and "Switch school or role" to this menu and shows
    * "role · school" under the name. Off by default so existing callers keep their menu. */
   showAccountControls?: boolean;
   ```
   When true, in this order (patterns.md §10 "AccountMenu"; items `min-h-11 gap-2.5 px-3`):
   1. identity block: name, then `{roleLabel} · {activeName}` (from `useTenantSwitch()`; omit the `· school` part when there is no active tenant);
   2. separator;
   3. `MenuSub` → `MenuSubTrigger`: `<LanguagesIcon />` + `t('language.groupLabel')` + `<span className="ms-auto text-text-secondary">{label(locale)}</span>`; `MenuSubContent`: `MenuRadioGroup value={locale} onValueChange={choose}` with one `MenuRadioItem` per `SUPPORTED_LOCALES` (clone `locale-switcher.tsx:68-75`);
   4. same for theme: `isDark ? <MoonIcon/> : <SunIcon/>` + `t('theme.groupLabel')` + current `t(`theme.${preference}`)`; sub-content clones `theme-toggle.tsx:56-71`;
   5. `profileItem` slot (the consumer's Security row lives here), unchanged;
   6. when `canSwitch`: `MenuSub` → trigger `<ArrowLeftRightIcon />` + `t('tenantBar.switchSchoolOrRole')`; sub-content = the same school / role lists `TenantBar` shows, each `onSelect={() => request(m)}`;
   7. separator, `installItem` slot (unchanged), Sign out (unchanged).
   Render the two hooks' sr-only announcers and `useTenantSwitch().overlay` as siblings of `<Menu>` (inside a fragment), never inside `MenuContent` — a portalled menu unmounts on close and would take the confirm dialog with it. `MenuSub*` already exist in `ui/src/components/menu.tsx:86-95`.
   With `showAccountControls` false or omitted the JSX is exactly today's (`:73-115`).
   - Trigger: `className="size-11 md:size-9"`; icon `CircleUserRoundIcon` (kit) instead of `UserIcon`; accessible name unchanged (`:83`).

6. **Stories.** `user-menu.stories.tsx`: add `AccountControls` (`showAccountControls`, a Security `profileItem`, a token with two memberships so the switch row shows; clone the token helper from `tenant-bar.stories.tsx`) and the same at `mobile1`. `locale-switcher.stories.tsx`: add `Labelled` (`trigger="labelled"`).
