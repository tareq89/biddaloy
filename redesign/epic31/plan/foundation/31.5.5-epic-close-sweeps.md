## Steps
1. **Read first:** `playwright.config.ts:91-115` (each browser has a PR project and a `-sweeps` project; sweeps are the specs whose top-level `describe` title ends in ` @sweep`), `e2e/a11y/routes.a11y.spec.ts:24-90` (variants: bn light, en light, bn dark), `e2e/responsive/reflow.spec.ts`, `e2e/responsive/target-size.spec.ts`, `e2e/responsive/routes.ts` (`routes` from the manifest, `resolvePath` fills `$param` segments by creating or finding data through the API), `e2e/a11y/overlay-openers.ts` (one opener per `route::overlay` key), `e2e/a11y/exceptions.ts` (the only allowed way to suppress an axe rule: reason + recheck date).
2. **Local run recipe** (`README.md` "Test infrastructure: one Docker stack, a slice per run"; never start new containers):
   ```bash
   ENV_FILE=$(yarn --silent test-env up)
   set -a; . "$ENV_FILE"; set +a; export E2E_BROWSERS=chromium
   yarn build:shared
   yarn workspace @biddaloy/server migration:run
   SEED_ATTENDANCE_DEVICE_KEY=bd_dev_seed_0000000000000000000000000000 yarn workspace @biddaloy/server seed
   npx playwright test --project=chromium-sweeps --reporter=list            # everything
   npx playwright test --project=chromium-sweeps -g "/fees/dues" --workers=1 # one route while fixing
   yarn test-env down
   ```
   Re-source `$ENV_FILE` in every new shell. Playwright starts server and client itself (`webServer`). The full sweep is long locally; the same run on CI is `gh workflow run nightly-e2e.yml --ref <branch>` (it has `workflow_dispatch` and runs `--project=chromium-sweeps` in 3 shards) — use it for the full pass and run single routes locally while fixing.
3. **Raise the phone gate (C2).** Below `md` every shell is now comfortable (31.1.1's `globals.css` media rule sets `--control-h: 2.75rem`), so in `target-size.spec.ts` replace the hard-coded `COMFORTABLE_ROUTES` list (`:166-172`) with every non-redirect manifest route (reuse the first loop's auth selection and `resolvePath`), still at `viewport: { width: 360, height: 640 }`, still 44 px. Replace the `data-density="comfortable"` attachment check (`:186`) — staff pages do not set that attribute — with a check on the mechanism that now applies to all shells: `getComputedStyle(document.documentElement).getPropertyValue('--control-h').trim()` equals `2.75rem`. Keep the 24 px loop for desktop as is. Update both header comments (they say staff stays dense, which is now only true at `md` and up) and the stale `/payments/record` redirect example in its `pageOrDialogHeading` comment (`:8-12`). Keep the `@sweep` tag.
4. **Overlays.** Wave 4 turned several dialogs into full-page modals (D22, D23) or renamed buttons. Run `npx playwright test e2e/a11y --project=chromium-sweeps -g "::"` (overlay tests) and fix each failing opener in `overlay-openers.ts`: a full-page modal is reached by its URL (search param or route) and has an `h1`, not `role="dialog"` — open it by URL and assert its `h1`. The manifest overlays today: `commit`, `send-reminder`, `create-schedule` (becomes full-page, D23), `create-structure`, `programForm`, `enrol`, `record`, `milestoneRemove`, `confirm-send`, `delete-student`. Rename a manifest overlay only if its meaning changed.
5. **Params.** If a detail route fails before the page loads, the cause is usually `resolvePath` (`routes.ts`): wave 4 added no routes (D1), so a failure means a fixture call broke — fix the resolver, do not drop the route.
6. **Fix or file each failure.**
   - Cause in shared code (`ui/src/**`, a layout, a locale file) → fix here, smallest change, with a unit test if logic changed.
   - Cause inside one page → file a GitHub issue titled `[31.0 follow-up] <route>: <rule>` with the failing sweep line, the screenshot from `test-results/`, and the page ticket that owned it; link it from #811. If it blocks the gate, add a time-boxed `a11yException(ruleId, 'tracked in #<n>', '<date ≤ 30 days>')` (a11y) or skip only that route's test with the issue number in the skip reason (reflow/target-size).
   - Never widen a threshold to make a test pass.
7. **Screen-reader pass** (`docs/architecture/15-ux-principles.md` §6: a manual pass closes every epic). VoiceOver (macOS) on `/students`, `/students/<id>`, `/fees/dues`, `/payments/record` (full-page modal), `/calendar`, and `/portal` at 390 px and 1440 px, bn: the `h1` is announced on navigation, row-action buttons announce their tooltip name, `StatusBadge` text is read, the drawer and full-page modal trap and return focus. File findings as issues; list them on #811.
8. **Matrix note.** The a11y sweep keeps its three variants (bn light, en light, bn dark): dark mode changes only colours, which `bn · dark` already checks for contrast, and en text is never longer than bn, so reflow/target-size run in bn only. Do not add variants.
9. **Close.** All `chromium-sweeps` tests green (or skipped with an issue number), the PR project `chromium` green, and the list of filed follow-ups in the PR description and on #811.
