# [31.3.6] ui — no "permission denied" toast just for opening a page

## Goal
Opening any page as a role without `SETTINGS_MANAGE` (accountant, teacher, parent…) shows no red toast (B8): the region-config query only runs for roles allowed to read school settings, and a 403 on a background **read** never toasts — only a 403 on something the user clicked (a mutation) does.

## Files
- `ui/src/i18n/use-tenant-region-config.ts` (changed) — gate the settings query on the permission.
- `ui/src/i18n/use-tenant-region-config.test.tsx` (changed).
- `ui/src/api/query-client.ts` (changed) — queries no longer toast on 403; mutations still do.
- `ui/src/api/query-client.test.ts` (changed).

## Steps
1. **Read first:** bug **B8** (`PLAN/kit/BUGS.md`); `ui/src/i18n/use-tenant-region-config.ts` (55 lines); `ui/src/api/query-client.ts` (81 lines). The endpoint is `GET /schools/:id/settings`, gated `@RequirePermissions(Permission.SETTINGS_MANAGE)` (`server/src/modules/schools/schools.controller.ts:66-67`); ~45 routes call `useTenantRegionConfig()`, so every role without that permission gets a 403 and a toast on every page.
2. **Gate the query** (`use-tenant-region-config.ts:46`):
   ```ts
   const canReadSettings = useHasPermission(Permission.SETTINGS_MANAGE);   // '../hooks/permissions' (ui/src/hooks/permissions.ts:29)
   const { data } = useQuery({
     ...schoolSettingsQueryOptions(tenantId ?? ''),
     enabled: tenantId !== null && canReadSettings,
     throwOnError: false,
   });
   ```
   `Permission` from `@biddaloy/shared`. A role without the permission gets the locale default (`LOCALE_REGION_DEFAULTS[locale]`, `:39`) — exactly what it gets today after the 403, minus the request and the toast. Add one sentence to the doc comment (`:29-35`) saying so.
   `ponytail:` roles without `SETTINGS_MANAGE` never see the school's own region settings (numerals, currency); the upgrade is a small read-only `GET /schools/:id/region` any member may call — out of scope here (no server work in this ticket); recorded as a deferred follow-up in `PLAN/kit/FOLLOW-UPS.md` ("read-only region settings for non-admins").
3. **Silent background reads** (`query-client.ts:21-25`, `:78-79`): split the handler.
   ```ts
   function handleMutationError(error: unknown): void { /* today's body: toast on 403 unless suspended */ }
   // queryCache: no onError toast — a page whose own data 403s shows its ErrorState / AccessDeniedState;
   // a background read the role may not make is a bug to gate at the call site (B9–B11 page tickets), not a toast.
   queryCache: new QueryCache(),
   mutationCache: new MutationCache({ onError: handleMutationError }),
   ```
   Update the doc comment (`:9-20`) to say reads are silent and why. Keep `throwOnError: isTenantSuspendedError` (`:72`) unchanged — the suspended-school page still comes from queries.
4. Check nothing relied on the query toast: `rg -n "permissionDenied" ui/src client-admin/src --glob '*.{ts,tsx}'` — only `query-client.ts` should use it; a test that expects a toast after a failed **query** is updated (step "Tests").

## Decisions settled here
- **403 toasts are silenced on reads only.** A query (page load, background refetch) that 403s shows nothing global — the page's own `ErrorState` / `AccessDeniedState` explains it. A mutation (something the user clicked) that 403s still toasts, because the user needs to know their action did not happen.
- Non-admin roles keep the locale's default region config (numerals, currency) until the read-only region endpoint exists (FOLLOW-UPS).
