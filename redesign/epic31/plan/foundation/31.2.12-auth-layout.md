# [31.2.12] ui — AuthLayout for every signed-out page

## Goal
`AuthLayout` (stubbed by 31.1.2) becomes the one guest-page frame of D34 — language switcher top right, logo + product name, one centred `max-w-md` card — and the sign-in / OTP / set-password forms drop their own logo and card when they sit inside it, so the guest page tickets (wave 4) only swap `AuthScreen` for `AuthLayout` in their routes.

## Steps
1. **Read first:** `PLAN/kit/patterns.md` §3 "AuthLayout"; `PLAN/kit/starter-guest.html` (or `PLAN/kit-build/starter-guest.body.html`); conflict C22; `client-admin/src/routes/-auth-screen.tsx` (what `AuthLayout` replaces: `useDensity('comfortable')`, `RegionConfigProvider` with no `value`, `max-w-sm`, a `ThemeToggle` the kit drops).

2. **`auth-layout.tsx`.** Keep the stub's export and props (`AuthLayoutProps { children: React.ReactNode; size?: 'default' | 'wide' }`, 31.1.2a step 12). The stub already moved `AuthScreen`'s density + region wiring in; this ticket swaps its icon `<LocaleSwitcher />` for the labelled one, adds the logo, product name and card, and the context. Final shape:
   ```tsx
   const AuthLayoutContext = React.createContext(false);
   /** True inside <AuthLayout>: the guest forms then skip their own logo and card. */
   export function useInsideAuthLayout(): boolean { return React.useContext(AuthLayoutContext); }

   export function AuthLayout({ children, size = 'default' }: AuthLayoutProps) {
     useDensity('comfortable');                 // '../hooks/use-density' — same reason as -auth-screen.tsx:14-21
     const { t } = useTranslation('nav');       // 'nav.brand', as the stub uses (auth.brand holds the same value)
     return (
       <RegionConfigProvider>                   {/* no value: no tenant yet, see -auth-screen.tsx:25-29 */}
         <AuthLayoutContext.Provider value>
           <div className="flex min-h-dvh flex-col bg-background">
             <div className="flex justify-end p-4 print:hidden"><LocaleSwitcher trigger="labelled" /></div>
             <main className="flex flex-1 items-start justify-center px-4 pt-4 pb-16 md:items-center md:pt-0">
               <div className={cn('w-full', size === 'wide' ? 'max-w-2xl' : 'max-w-md')}>
                 <div className="mb-6 flex flex-col items-center gap-2 print:hidden">
                   <span aria-hidden="true" className="flex size-12 items-center justify-center rounded-lg bg-primary text-primary-foreground"><SchoolIcon /></span>
                   <p className="text-h3">{t('brand')}</p>
                 </div>
                 <section className="rounded-lg border border-border-subtle bg-surface p-4 shadow-e1 md:p-5 print:border-0 print:p-0 print:shadow-none">{children}</section>
               </div>
             </main>
           </div>
         </AuthLayoutContext.Provider>
       </RegionConfigProvider>
     );
   }
   ```
   - `useInsideAuthLayout` is imported by the three forms from `./auth-layout` only — no barrel export.
   - `size="wide"` (shared request admission_slug) is only for the long public admission form; every other guest page keeps the D34 `max-w-md` card.
   - `print:` classes (shared request i_token): "Save as PDF" on `/i/$token` prints only the receipt — language row and logo block hidden, card frame dropped.
   - No `ThemeToggle` (C22: guest pages follow the system / stored theme). `LocaleSwitcher trigger="labelled"` comes from 31.2.9b.
   - `<main>` without an `id`: guest pages have no `AppShell`, and `useRouteFocus` (`client-admin/src/routes/__root.tsx:155-162`) already falls back to the form's own `<h1>` — giving this `<main>` the `APP_SHELL_MAIN_ID` would change that focus target.

3. **Forms — frame only outside `AuthLayout`, kit heading everywhere.**
   - `sign-in-form.tsx`: `const framed = !useInsideAuthLayout();`. Brand block (`:151-159`) renders only when `framed`. The `<form>` class (`:165`) becomes `cn('flex flex-col gap-5', framed && 'rounded-lg border border-border-subtle bg-card p-8')`. Heading block (`:167-170`): `<div><h1 className="text-h1 text-balance">…</h1><p className="mt-0.5 text-text-secondary">…</p></div>` (left-aligned, patterns.md §3 "AuthLayout" / starter-guest).
   - `otp-sign-in-form.tsx`: same for `brandMark` (`:180-190`, rendered at `:195` and `:254`), the two card wrappers (`:196`, `:259`) and both heading blocks (`:197`, `:261`).
   - `set-password-form.tsx`: card class (`:173`) → `cn('flex flex-col gap-5', framed && '…border… p-8')`; heading block (`:175-178`) as above.
   - `school-picker.tsx`: heading block (`:97-100`) as above (no frame logic needed).
   - Outside `AuthLayout` (today's routes, still using `AuthScreen` until wave 4) the forms keep their logo and card, so no route changes in this wave; only the heading turns left-aligned `text-h1`.

4. **Stories.** `auth-layout.stories.tsx`: `SignIn` (`<AuthLayout><SignInForm … /></AuthLayout>`, args cloned from `sign-in-form.stories.tsx`), `SetPassword`, `SchoolPicker`, each also at `mobile1`; one dark story using the repo's `darkDecorator` + `darkDecoratorParameters` pair (see `09-design-direction.md:540-547`).
