# [31.2.5a] ui — shells: PageContainer + PageHeader in List, Form and Wizard shells

## Goal
`ListShell`, `FormShell` and `WizardShell` render their content inside one centred `PageContainer` and their title through one `PageHeader` (h1 + optional subtitle + tiered actions that collapse into "More" on phone), so every shell page has the same width and header (D15, D16).

2. **`page-container.tsx`**:
   ```ts
   export interface PageContainerProps { size?: 'wide' | 'narrow'; children: React.ReactNode }
   ```
   `<div data-slot="page-container" className={cn('mx-auto w-full space-y-6', size === 'narrow' ? 'max-w-3xl' : 'max-w-screen-xl')}>` (default `wide`).
   **No padding here** — deliberate deviation from `patterns.md` (`px-4 py-4 md:px-6 md:py-6`): `<main>` in `ui/src/components/app-shell.tsx:527` already pads every page (`p-6`), and 54 of 103 leaf routes render no shell, so moving the gutter into the container would either double it on shell pages or remove it from shell-less pages until wave 4. 3. **`page-header.tsx`** — types (own them here; `detail-shell.tsx` re-aliases them in 31.2.5b):
   ```ts
   export type PageActionPriority = 'primary' | 'secondary' | 'tertiary' | 'destructive';

     allowed?: boolean; priority?: PageActionPriority; icon?: React.ReactNode;
     disabled?: boolean;   // shared request exams_templates_templateId: Save stays visible but disabled until dirty

   ```

   - `PageHeaderActions({ actions })` — move the tiering from `ui/src/shells/detail-shell.tsx:95-185` here and extend it:
     - `visible = actions.filter(a => a.allowed !== false)`; tier default `'secondary'` (keep the dev `console.warn` for >1 primary, `:118-125`, text now says "PageHeader").
     - `menuBase = [...secondary.slice(2), ...tertiary]`; `destructiveInline = menuBase.length === 0 && secondary.length < 2 ? destructive.slice(0, 2 - secondary.length) : []`; `destructiveMenu = destructive.filter(a => !destructiveInline.includes(a))`.
     - Desktop inline, in this order: `secondary.slice(0, 2)`, `destructiveInline`, then the one primary. Desktop menu: `menuBase`, a `MenuSeparator` when both it and `destructiveMenu` are non-empty, then `destructiveMenu` (`variant="destructive"`). This keeps today's "a lone destructive stays inline" rule and caps outline buttons at 2 (D16).
     - Variants: primary `default`, secondary `outline`, destructive `destructive` (tinted). Icon (when given) renders before the label.
     - `disabled` → inline `Button disabled` and `MenuItem disabled`; `busy` → inline `Button loading={busy}` and `MenuItem disabled` while busy. Never hide an action because it is disabled.
     - **Phone (D16)**: every inline non-primary button gets `className="hidden md:inline-flex"` (`cn` keeps `md:inline-flex` and drops the base `inline-flex`; never add `hidden` by string concat). The same actions are added to the top of the menu as `MenuItem className="md:hidden"`. The primary gets `className="flex-1 md:flex-none"`. The More trigger renders when the phone menu (inline non-primary + desktop menu) is non-empty; when the desktop menu itself is empty the trigger gets `className="md:hidden"`.
