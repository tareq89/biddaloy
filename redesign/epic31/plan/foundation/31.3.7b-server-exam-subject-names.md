# [31.3.7b] server — exam responses name their subjects (marks progress, seat-plan sittings)

## Goal
Two exam-domain responses that today hand the page a bare `subject_id` or only the English subject name carry the subject's names (and, for seat-plan sittings, the date and time) as small additive fields, so the marks page and the seat-plan page never show an id or an English-only name on a Bangla screen (D9). Nothing is removed or renamed.

## Files

- `server/src/modules/exams/mark-grid.service.spec.ts` (changed).
- `server/src/modules/exams/mark-grid.integration.spec.ts` (new, or the existing exams integration spec if one covers `progress` — `rg -ln "progress\(" server/src/modules/exams/*.integration.spec.ts` first).

- `server/src/modules/seat-plans/seat-plans.service.ts` (changed) — each allocation row in `findOne` gains `subject_name_bn`, `exam_date`, `starts_at`, `ends_at`.
- `server/src/modules/seat-plans/seat-plans.service.spec.ts` (changed).

## Steps
1. **Read first:** `server/CLAUDE.md` (vitest; `*.spec.ts` unit with mocked repos, `*.integration.spec.ts` real DB; tenant A ≠ tenant B and soft-delete cases are mandatory), `.claude/skills/multi-tenancy/SKILL.md` (every joined tenant table filters `tenant_id` by hand). No route, guard, permission or DTO class changes: both responses are hand-typed on the client (`ui/src/hooks/exams.ts:447` comment, `ui/src/hooks/seat-plans.ts:82-87`), so `schema.d.ts` does not change for them.
2. **Marks progress** (`mark-grid.service.ts:372-430`, request from marks-1). The components query (`:388-390`) already holds every `subject_id`; load the subject with it:
   ```ts
   this.componentRepo.find({
     where: { exam_id: examId, tenant_id: tenantId, deleted_at: IsNull(), subject: { tenant_id: tenantId } },
     relations: { subject: true },
     withDeleted: true,   // a soft-deleted subject still names its outstanding grid; the component's own deleted_at stays filtered above
   }),
   ```
   Build `const subjectById = new Map(components.map((c) => [c.subject_id, c.subject]))` and push
   `subject_name: subjectById.get(subjectId)?.name_en ?? null, subject_name_bn: subjectById.get(subjectId)?.name_bn ?? null` on each outstanding row. Widen the return type (`:376-383`, `:405-410`) to `subject_name: string | null; subject_name_bn: string | null`. `ExamComponent.subject` exists (`exams/entities/exam-component.entity.ts:35`); no new repository injection.
3. **`ui/src/hooks/exams.ts`** `ExamProgress.outstanding[]`: add `subject_name: string | null; subject_name_bn: string | null;`. Nothing else in the file changes.
4. **Seat-plan sittings** (`seat-plans.service.ts:416-426`, request from exams-4b). `findOne` already loads `exam_schedule: { subject: true }` (`:375-378`, again at `:716-719`). In the allocation map add, next to `subject_name`:
   ```ts
   subject_name_bn: allocation.exam_schedule?.subject?.name_bn ?? null,
   exam_date: allocation.exam_schedule?.date ?? null,        // 'YYYY-MM-DD'
   starts_at: allocation.exam_schedule?.starts_at ?? null,   // 'HH:mm:ss'
   ends_at: allocation.exam_schedule?.ends_at ?? null,
   ```
   (`ExamSchedule.date/starts_at/ends_at`, `exams/entities/exam-schedule.entity.ts:64-70`.) Apply the same map wherever the publish path re-builds the rows (`:710-720`) — one shared mapper function, not two copies. The page asked for a separate `schedules[]` array; these four fields on the rows it already groups by `exam_schedule_id` give it the same data without a second structure.
5. **`ui/src/hooks/seat-plans.ts`** `SeatPlanAllocationRow`: add `subject_name_bn: string | null; exam_date: string | null; starts_at: string | null; ends_at: string | null;`.
6. Do not regenerate `schema.d.ts` (31.3.7d does it once for the lane).
