# [31.3.7a] server — list responses carry names (holiday sets, intakes, audit log)

## Goal
Three list endpoints return what their pages need to show a name instead of crashing or showing an id: the holiday-set list includes its entries (B7), the admission-intake list includes class and section names (B12), and each audit-log row carries an `entity_label` (B14) — every lookup tenant-scoped. First ticket of the wave-3 "server" lane (31.3.7a → 7b → 7c → 7d); `ui/src/api/schema.d.ts` is regenerated once, by 31.3.7d, for all four.

3. **Intakes (B12)** — `intake.service.ts:39-45`.   
   ```ts
   async findAll(tenantId: string): Promise<IntakeListRow[]> {
     const intakes = await this.repo.find({
       where: {
         tenant_id: tenantId,
         deleted_at: IsNull(),
         class_section: { tenant_id: tenantId, class: { tenant_id: tenantId } },   // joined rows scoped too (multi-tenancy rule)
       },
       relations: { class_section: { class: true } },
       withDeleted: true,       // a soft-deleted section/class must still name the intake; the intake's own deleted_at stays filtered above
       order: { created_at: 'DESC' },
     });
     return intakes.map(({ class_section, ...intake }) => ({
       ...withStatus(intake as AdmissionIntake),
       class_name: class_section?.class?.name ?? null,
       section_name: class_section?.section_name ?? null,
     }));
   }
   ```
   `type IntakeListRow = IntakeWithStatus & { class_name: string | null; section_name: string | null }` next to `IntakeWithStatus` (`:9`). The nested object is dropped so the list stays flat. The controller (`intake.controller.ts:39-43`) has no response DTO, so `schema.d.ts` does not change for this endpoint; the client type is hand-written in `client-admin/src/features/admission/hooks/useIntakes.ts:28-39` and page ticket `admissions-3` adds the two fields and renders them (`IntakeList.tsx:48-51`).
