# [31.3.5] client-admin — breadcrumbs: names instead of ids, skeleton while loading, row only at 2+ levels

## Goal
No breadcrumb ever shows a UUID (D9, B16): detail pages show the entity's name read from the query cache, a skeleton bar while it loads (C5), or the generic noun when there is no name to read; and the crumb row only renders when the trail has 2 or more crumbs (C7), while `document.title` still comes from the trail.

3. **Resolver shape** (`use-breadcrumbs.ts:58-104`): today each resolver reads one exact key with `useQuery({ enabled: false })` (`:118-134`); PR #1407 already widened `getName` to `(data, id)` for a list-shaped cache (`:66-67`, used by `myClassSection`) — the new shape below keeps that `id` argument, so a page whose cache key carries extra parts (the attendance register key has date + period) can never be resolved. Replace with a prefix read of the cache:
   ```ts
   type CrumbContext = { language: string; region: RegionConfig };   // i18n.language + useRegionConfig(), for names built from dates/numbers
   type EntityResolver = {
     param?: string;                                          // which route param is the id (default: the first one)
     queryKeys: (id: string, params: Record<string, string>) => readonly QueryKey[];   // prefixes; first match wins
     getName: (data: unknown, id: string, ctx: CrumbContext) => string | undefined;
   };
   function useCachedEntityName(entityKey: string | undefined, params: Record<string, string>, ctx: CrumbContext): string | undefined {
     const id = resolver?.param ? params[resolver.param] : Object.values(params)[0];
     const queryClient = useQueryClient();
     const resolver = entityKey ? ENTITY_RESOLVERS[entityKey] : undefined;
     const read = () => {
       if (!resolver || !id) return undefined;
       for (const key of resolver.queryKeys(id, params))
         for (const [, data] of queryClient.getQueriesData({ queryKey: key }))
           if (data !== undefined) { const name = resolver.getName(data, id, ctx); if (name) return name; }
       return undefined;
     };
     return React.useSyncExternalStore((cb) => queryClient.getQueryCache().subscribe(cb), read, read);
   }
   ```
   (Declare `resolver` before the `id` line; the sketch is about shape, not order.) It still never fetches (the module comment `:38-56` stays true; update its "registered entities" paragraph). `read` returns a string or `undefined`, so `useSyncExternalStore` re-renders only when the name changes.
