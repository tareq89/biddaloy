# [31.2.1a] ui — date & time formatters: long dates, Bangla ordinals and day-parts, month, time, ranges

## Goal
`formatDate`, `formatDateTime`, `formatMonth`, `formatTime` and `formatDateRange` produce the D5/D7
display forms in both languages, take a `Date` or the API's strings, and never throw (empty or bad
input → `—`). `formatDate` changes **in place** (D5 "one function each"), so every existing call
site switches to the long form with no route edit.

## Files
- `ui/src/components/attendance-month-grid.test.tsx` (changed) — date-carrying accessible names built from the formatter (test only)
- `ui/src/utils/date.ts` (changed) — new bodies for `formatDate`, `formatDateTime`, `formatMonth`, `formatTime`, `formatDateRange`; private helpers
- `ui/src/utils/date.spec.ts` (changed) — the assertions listed under Tests
- `ui/src/i18n/region-config.spec.ts` (changed) — `:83` only

## Steps
1. **Language and digits.** Inside `date.ts` add private helpers:
   - `isBangla(config) = config.locale.startsWith('bn')` — picks ordinals and day-part words.
   - Digits always via `renderDigits(…, config.numerals)` (`./digits`) — never `Intl` digits, so a
     `bn` tenant with Latin numerals (or the reverse) stays consistent (D6).
   - `monthName(m1to12, config)` = existing `formatMonthName` (added by 31.1.2b; keep it). **Signature is fixed and public:** `formatMonthName(month: number, config: RegionConfig): string` with `month` **1–12** (January = 1, not a JS `getMonth()` 0–11 index). MonthPicker (31.2.2) and page tickets call it with 1–12. Out-of-range or non-integer `month` → `'—'` (add that guard to the 31.1.2b body; it is the only change to it).
2. **Ordinals (D5).** Private `dayOrdinal(day: number, config): string`:
   - Bangla — exactly this table (D5): `1 → ১লা`, `2 → ২রা`, `3 → ৩রা`, `4 → ৪ঠা`, `5–18 → <n>ই`,
     `19–31 → <n>শে`. Suffix is chosen by the number; the number itself goes through
     `renderDigits` (so Latin-numeral bn gives `9ই`).
   - English — `1st 2nd 3rd`, `4th…20th`, `21st 22nd 23rd`, `24th…30th`, `31st` (rule: 11–13 → `th`;
     else last digit 1/2/3 → `st/nd/rd`; else `th`).
3. **Parsing (never throws).** Private `toParts(value, config, mode)` returning
   `{ y, m, d, hh?, mm? } | null`:
   - `null`/`undefined`/`''` → `null`.
   - `Date` → `null` if `isNaN(value.getTime())`. For `formatDate`/`formatMonth`/`formatWeekday`
     use **local** calendar fields (`getFullYear/getMonth/getDate`) — same as today's `formatDate`
     (`date.ts:12-17`), which is what `parseDate`/`parseServerDate` callers rely on. For
     `formatDateTime`/`formatTime` use the tenant clock: copy the `Intl.DateTimeFormat('en-CA',
     { timeZone: config.timezone, …, hourCycle: 'h23' }).formatToParts` block from today's
     `formatDateTime` (`date.ts:29-39`).
   - string `HH:mm` or `HH:mm:ss` (`/^(\d{1,2}):(\d{2})(?::\d{2})?$/`) → wall-clock time, no
     time-zone maths (`formatTime` only).
   - string `YYYY-MM` (`formatMonth` only) → `{ y, m }`.
   - string starting `YYYY-MM-DD`: for `formatDate`/`formatMonth`/`formatWeekday` take the first
     10 chars (Postgres `date` column semantics, same reason as `parseServerDate`, `date.ts:71-87`);
     for `formatDateTime`/`formatTime` a string longer than 10 chars is an instant → `new Date(value)`
     → tenant clock as above.
   - Validate the calendar date (reject `2026-02-30`, like `parseDate` `:64`) → `null`.
   Every public function returns `'—'` when parts are `null`.
4. **Bodies.**
   - `formatDate(value: Date | string | null | undefined, config)` → en `9th September, 2026`, bn
     `৯ই সেপ্টেম্বর, ২০২৬` = `${dayOrdinal(d)} ${monthName(m)}, ${renderDigits(y)}`. Rewrite the doc
     comment (`date.ts:5-11`): long form per D5; ISO for data is `toIsoDate`.
   - `formatDateTime(value, config)` → `${formatDate part}, ${time part}` where time part is the
     `formatTime` rule below: en `9th September, 2026, 3:45 PM`, bn `৯ই সেপ্টেম্বর, ২০২৬, বিকাল ৩:৪৫`.
     Keep the tenant-clock comment (`:26-28`).
   - `formatMonth(value, config)` → `${monthName(m)} ${renderDigits(y)}`: `October 2026` / `অক্টোবর ২০২৬`.
   - `formatTime(value, config)` (D7, C19) — 12-hour, no seconds, hour not padded, minutes padded:
     - en: `${h12}:${mm} ${hh < 12 ? 'AM' : 'PM'}` → `8:00 AM`, `12:30 PM`, `12:05 AM`.
     - bn: `${word} ${h12}:${mm}` with this table by 24-hour `hh` (patterns.md §11, not `Intl`,
       which says "অপরাহ্ণ"): `0–3 রাত` · `4–5 ভোর` · `6–11 সকাল` · `12–14 দুপুর` · `15–17 বিকাল` ·
       `18–19 সন্ধ্যা` · `20–23 রাত` → `সকাল ৮:০০`, `রাত ১২:০০` for 00:00.
     - `h12 = hh % 12 || 12`; digits through `renderDigits`.
   - `formatDateRange(from, to, config)` (patterns.md §11 last bullet): parse both as dates; if
     either is `null` → `'—'`; same day → `formatDate(from)`; same month and year → en `8th – 10th October`,
     bn `৮ই – ১০ই অক্টোবর` (no year); same year → `28th September – 3rd October, 2026` /
     `২৮শে সেপ্টেম্বর – ৩রা অক্টোবর, ২০২৬`; otherwise `${formatDate(from)} – ${formatDate(to)}`.
     Separator is space, en dash, space.
   - Leave `formatWeekday`, `formatMonthName`, `toIsoDate`, `parseDate`, `parseServerDate`,
     `isPastDueDate`, `getAcademicYear`, `formatAcademicYear`, `formatRelativeAge` as they are.
5. Keep the file free of `toLocale*String`; only `Intl.DateTimeFormat` for month names and the
   tenant-clock parts.
