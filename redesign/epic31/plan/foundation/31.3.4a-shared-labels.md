# [31.3.4a] i18n — shared labels: glossary, nav.json, common.json, missing crumb keys

## Goal
`nav.json` and `common.json` carry the plain glossary wording (D32), every key the crumbs ask for (B15), the bottom-bar short labels and translated enum labels (D9), in en and bn — so the wave-3 layout and crumb tickets can build on them.

**Lane rule:** 31.3.4a then 31.3.4b are the ONLY wave-3 tickets that touch `ui/src/i18n/locales/**`. Run 31.3.4a **first** in wave 3 (31.3.1, 31.3.2, 31.3.3, 31.3.5 depend on its keys), then 31.3.4b, one after the other in one lane. No other ticket edits a locale file meanwhile.

## Files
- `ui/src/i18n/locales/en/nav.json`, `ui/src/i18n/locales/bn/nav.json` (changed) — B1, B2, B3.
- `ui/src/i18n/locales/en/common.json`, `ui/src/i18n/locales/bn/common.json` (changed) — B4.
- Any unit test / e2e spec that hard-codes a changed nav string (step 4).

## Steps
1. **Read first:** `PLAN/kit/DECISIONS.md` D9, D16, D32; conflict **C23**; bug **B15**; section A below (the glossary — it is also the rule 31.3.4b and every wave-4 page ticket apply inside their own namespaces).
2. Edit en and bn together for every key; keep `{{placeholders}}` and `_one/_other` suffixes. Parity is enforced by `ui/scripts/check-i18n-keys.mjs` (`yarn workspace @biddaloy/ui check:i18n`; CI runs it at `.github/workflows/ci.yml:220`). The checker cannot see computed keys like `t(`items.${key}`)` (`client-admin/src/use-breadcrumbs.ts:189`) — that is why B15 slipped through; B2 adds every key `route-crumbs.ts` names.
3. Apply B1–B4 exactly. Do not delete keys (`nav.userMenu.profile*` becomes unused after 31.3.1 — leave it for the unused-key report).
4. For each changed nav label run `rg -n "<old en value>|<old bn value>" e2e client-admin/src ui/src --glob '*.{ts,tsx}'`; a test asserting the old literal must read it through `t()` / `e2e/i18n.ts` instead.
